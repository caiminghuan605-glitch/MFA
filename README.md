# 铜需求分配与矿山用水核算（MFA / 用水）

本仓库实现两步核算：

1. `01_allocate_copper.py`：把"情景 × 年份 × 工艺路线"的既有铜需求，按**对应年份**的矿山铜产量权重分配到矿山（t Cu）；

结果写入 `C:\Users\22965\OneDrive\桌面\MFA\Output\铜需求分配与用水核算.xlsx`，**只有两张表**：`铜需求分配`、`用水核算`。

> 本 README 中的全部数字均为本次实际运行的输出（不是示意值）；算例一节单独说明其为真实记录。

## 2. 单位与产品口径

| 量 | 符号 | 单位 | 说明 |
|---|---|---|---|
| 铜需求 | D[s,t,r] | t Cu | 火法/湿法两条路线分别给量 |
| 矿山产量 | P[i,t] | t Cu | 含铜金属量 |
| 分配量 | A[i,s,t,r] | t Cu | A = D × w |
| 产物实物量 | Q | t 产物 | 火法=铜精矿；湿法=阴极铜 |
| 产物含铜率 | c | t Cu / t 产物 | 火法 0.362870–0.365814；湿法 1.0 |
| 用水系数 | k | m³ / t 产物 | 地区 × 路线 |
| 用水量 | W | m³ | W = Q × k |

火法路线：用户口语"精铜矿"经核对即 **铜精矿（Concentrate）**，不是"铜金属吨"。
湿法路线：SX-EW 矿山产物是 **阴极铜**；需求阶段为精炼铜（阴极铜），故按 1:1（t Cu/t 产物）换算。

## 3. 计算方法

### 3.1 分配（程序一）

对每个 `(情景 s, 年份 t, 路线 r)`：

```
E[s,t,r] = { i | route(i)=r 且 P[i,t] > 0 }        # 当年可参与矿山
w[i,s,t,r] = P[i,t] / Σ_{j∈E} P[j,t]               # 组内份额
A[i,s,t,r] = D[s,t,r] × w[i,s,t,r]                  # 分配量
未分配[s,t,r] = D[s,t,r] − Σ_i A[i,s,t,r]           # 实测恒为 0
```

- 权重**只用该年份**的产量（2021 用 2021 年列、2050 用 2050 年列），不存在"用基准年占比外推"。
- 同一矿山若跨路线，先按路线份额拆分产量再进各自分母；当前数据均为单一标签，份额=1。
- 需求为 0 → A=0；分母为 0 且需求>0 → 写缺口行并报错级告警（本次未出现）。

### 3.2 产物量与用水量（程序二）

```
火法：Q[i,s,t] = 铜精矿实物量[s,t] × w[i,s,t,火法]   （等价 Q = A / c）
湿法：Q[i,s,t] = A[i,s,t] / 1.0
W[i,s,t,r]    = Q[i,s,t,r] × k[地区(i), r]
W_total[s,t]  = Σ_i,r W[i,s,t,r]
```

**为什么火法不重新用品位换算**：既有需求面板已给出与冶炼收率链一致的"铜精矿实物量"，直接按同一组权重分摊即可，避免二次换算引入口径漂移。程序同时输出 `c = 组内火法铜 / 组内铜精矿实物量`，并逐行校验 `Q = A / c`（实测最大相对误差 9.58e-13）。湿法 1:1 的依据是需求阶段本身就是阴极铜。

### 3.3 年度权重如何决定（回答"是否用了对应年份"）

程序按 `年份` 列直接取当年产量列，逐 (年份, 路线) 重新归一：

- 2021 年可参与矿山 546 个（火法 446、湿法 100），组内产量合计 24.56 Mt Cu；
- 2030 年 568 个（火法 461、湿法 107），31.38 Mt Cu；
- 2050 年 400 个（火法 319、湿法 81），21.42 Mt Cu。

（可参与矿山数随开采周期与产量预测变化，权重每年重算。）

### 3.4 参考产能怎么用

- **不截断、不筛选、不设上限、不因超过产能判为不可满足**；
- 仅输出参考列与 `分配量 / 参考产能` 比值。两者同为 t Cu/年，口径一致；
- 分配量是"需求份额"，本来就可能远小于产量/产能（例如 2050 年 SSP1-2.6 的分配量约为当年矿山产量的 36%），比值仅用于观察扩产压力，不改变结果。

## 6. 含铜率、回收率、干湿基与单位换算

- 火法产物含铜率 `c = 铜精矿含铜量 / 铜精矿实物量`，实测仅 3 个取值：**0.365814（2021–2025）、0.364957（2026–2030）、0.362870（2031–2050）**，跨情景一致。
- 该值来自既有冶炼质量收率链（精矿→阴极铜），高于行业常见精矿品位 25–30%，属**沿用上游口径**，未自行改动。
- **回收率不重复扣除**：既有收率链已包含各工序收率，本程序不再乘任何回收率。
- **干湿基**：既有"铜精矿实物量"未注明干湿基，本程序不做水分换算，结果列标为"未注明（沿用既有质量收率链实物量）"；湿法阴极铜标为"不适用（金属阴极铜）"。
- 含铜率为百分数时先转质量分数（本次源数据已是 0–1 小数，无需转换）。
- t Cu、t 产物、m³、百万 m³ 的换算：1 百万 m³ = 10⁶ m³。

## 9. 算例（真实记录，非示意）

情景 `SSP1-2.6|基准|不开放`，年份 2021，矿山 `50 Let Oktyabrya`（Kazakhstan，其他亚洲，火法）：

1. 当年产量 `P = 45,000 t Cu`；组内火法产量合计 `ΣP = 19,336,974.772 t Cu`；
2. 权重 `w = 45,000 / 19,336,974.772 = 0.002327…`；
3. 组内火法需求 `D = 1,359,922.507 t Cu` → `A = D × w = 3,164.74079 t Cu`；
4. 组内铜精矿实物量 `= 3,717,525.954 t`，含铜率 `c = 1,359,922.507 / 3,717,525.954 = 0.365814`；
5. 产物量 `Q = A / c = 8,651.232672 t 铜精矿`（等价 `= 3,717,525.954 × 0.002327…`）；
6. 地区系数 `k = 140 m³/t 产物`（其他亚洲 · 精矿矿山（浮选））；
7. 用水量 `W = 8,651.232672 × 140 = 1,211,172.574 m³ = 1.211173 百万 m³`。

程序内逐行校验：`Q × c = 3,164.740790 t Cu`（= A），`Q × k = W`（完全一致）。

## 14. 数据缺口、假设与局限

1. **用水系数无出处/无指标定义**：源表只有 7 地区 × 2 列数值，未注明单位、取水/耗水、干湿基。本方案按用户确认的"m³/t 产物、用水量"使用；若原始来源实为 m³/t Cu，用水量将降为现结果的 **36.3–36.6%**（即乘以隐含含铜率）。
2. **隐含精矿品位偏高**：0.362870–0.365814 高于行业常见 25–30%，会低估铜精矿实物量（相对 28% 品位约低 23–25%），进而低估火法用水量。因用户要求直接使用既有铜精矿实物量，未改口径。
3. **路线口径不完全一致**：火法/湿法需求量沿用上一轮"矿山路线映射"（含 10 个混合矿份额、7 个多产品/非铜产品矿未知），本次矿山归组按当前简化标签（R1–R4）。总量守恒不受影响，但组内权重结构可能变化（如 Kamoa-Kakula 归入湿法）。
4. **需求为精炼铜，矿产量为含铜量**：分配量是需求份额而非生产计划，可大于/小于矿山当年产量与参考产能；未做截断，也未反推冶炼产能约束。
5. **疑似重复记录**：9 对同名同国记录（坐标相近、产能/产量不同）保留为独立记录，可能对个别矿山权重有轻微影响。
6. **运营期字段不完整**：投产/退役年分别缺失 52/312 行，且与产量存在少量冲突（0.16%/0.54%），故以产量为准入、年份仅作标记。
7. **未知路线矿未分配**：Leigh Creek（Cement 标签）产量占 0.0083%，不进入任何路线分母。
8. **面板非平衡**：未对缺失年份补零或插值；跨年比较时应结合 `数据质量标记` 与各年矿山池规模理解。
9. **结果文件未纳入 Git**：最终 Excel 位于仓库外的 `MFA\Output`（70 MB），仓库按"只提交程序、说明与必要配置"的要求仅跟踪代码与文档；结果可通过两条命令完整复现，sha256 见 §12.1。
